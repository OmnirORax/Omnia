# UI layout and templates

React Rnd supplies established drag, resize, bounds and grid behavior for windows and frames. Native desktop HTML drag-and-drop moves function references. A small occupied-cell layer implements irregular frame outlines; no dashboard or second editor framework is introduced. The primary interaction is desktop mouse input; touch-specific arrangement is not implemented.

`src/ui/layout.ts` validates the version-1 UI layout. Stable function IDs refer to runtime controls in App's registry; saved data contains no callbacks, graph IDs, or captured entity targets. Frame members use integer cells. Adjacent slots are chosen deterministically, and normalizing the origin preserves the positions of existing members. Empty frames have one slot. Function groups start collapsed; an explicitly created empty frame starts expanded so it can receive its first function. Removing a frame returns its controls to their original locations.

`FloatingWindow` portals windows to the document body, avoiding renderer/container coordinate offsets. It persists position, size, collapse and pin state; viewport fitting keeps imported geometry reachable. `UIPanel` reuses existing inspector/editing content rather than cloning editing implementations. Icon-only setting controls open a window containing their original field. Pinning locks position/size and frame membership; functions retain their original click behavior and disabled state.

`EntityMenu` saves action slots by menu kind. Membership and the target remain supplied by the workspace on each right-click. Its drag payload is separate from global function dragging. The menu cannot be detached from the target or have its actions moved elsewhere. Resizing and internal arrangement do not create semantic graph edits.

Version-3 `omnium-ui-template` files contain `layout` and optional normalized workspace `settings`. The layout includes embedded image assets and rejects missing frame/icon references, duplicate slots, invalid coordinates and excessive size. These assets are separate from graph assets. Import validates before applying either UI layout or settings. It never imports canonical entities, placements, relationships or investigations. Legacy combined template imports remain available with confirmation.

`src/ui/default-template.json` is the website default for browsers without a saved UI layout. Replace it with the user's exported version-3 template when they provide one; optional settings become defaults only when the browser has no saved settings. Existing browser customizations take precedence. `Reset UI arrangement` returns to the original empty arrangement and does not delete graph data or change keybindings. Graph undo history remains dedicated to graph edits; UI layout persists independently, so export templates to keep alternate arrangements.

Unknown function IDs are retained and shown as unavailable rather than silently discarded. Add future global controls to the function registry and render them with `FunctionControl`; entity-bound editing remains inside its owning panel/menu. New node-option categories still require developer changes. None of this changes Omnic semantics or the version-2 structural schema.
