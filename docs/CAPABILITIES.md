# Omnia capabilities and how to use them

Generated from the reviewed capability catalog and the live command/gesture registries. Edit `docs/capabilities/catalog.json`; run `node --run docs:capabilities`.

This is the user guide and the first place workers check before proposing a duplicate feature. It describes this branch, not proof that every feature has reached production. **Browser acceptance is unrecorded unless an entry says otherwise.** Cloud rollout and provider configuration are separate from implementation.

Find a feature by name in the index or command table. Open the relevant owner/frame first: contextual commands can be unavailable until that owner is mounted. Custom layouts can move controls; UI search and Shortcuts show registered names and your actual saved bindings. Catalog defaults below may differ from your settings.

Use disposable work for tests; export your workspace first. Each numbered step includes its expected result. Record failures and observed results against the stable capability ID; do not mark a test passed from builds alone.

## Active context, close, minimize, resize and descendants

**ID:** `interface.context` · **Status:** Implemented; browser verification pending

**Where:** Master controller → Active context. Click the intended frame first.

Actions target the clicked/focused frame. Esc steps out one field/popup level before minimizing; active MS has priority. W resizes/restores, M minimizes/restores, X closes, D toggles descendants, subject to saved bindings. Resized windows retain projected bounds and themed borders across focus and minimize/reopen. W restores retained original geometry. Projection styling is independent of React/Rnd wrapper updates. Left-clicking empty space dismisses all open contextual dials and requested dial editors, consuming that press so it does not also draw or begin a world gesture. Dial ×/close buttons are removed; the middle circle remains an unlabelled origin marker at full opacity. Category Back and Escape still step outward. Controls and rendered target roles retain their own click handling. Empty-space dismissal preserves chosen presets and accepted settings. Registered geometry surfaces now supply target adapters to the same commands and shortcuts; frame-only controls remain frame-only. MC discovers contextual controls from the command catalog rather than a parallel geometry toolbar. Delete selection and Compact are projected there. Popup/value-field Escape still precedes geometry scope and its parent frame. Shared active layers expose advance/confirm callbacks. Alt+MB4 steps outward, Alt+MB5 advances the nearest declared stage, Enter confirms, and Escape cancels or steps outward. Plain MB4/5 retain configured history behavior. Omnic dials have no Back/Confirm/checkmark navigation buttons; their centers only drag. Native input Enter remains local. Shared active-layer opening guards identify the physical press at window capture. Child React capture handlers cannot leave the native release guard armed for subsequent presses; only the original opener tail is suppressed. Keyboard-native activation retains its existing exception. Active MS picking retains the source editor navigation context instead of activating a pointed frame. A contextController window does not activate on automatic opening/inspection-key refresh. Accepted selection yields Esc to an editor or held gesture; an active picker retains its existing priority. Physical surface checks use the original event path rather than mutable SVG ancestry. Normal MS sessions opened on a registered content surface are bounded to that source root/context. The selector cursor and hover/wheel targeting apply there; a primary/secondary press or focus change on other controls ends normal targeting without consuming the control input or clearing accepted membership. Selector-owned configuration remains usable. ActiveContext preserves the source only for pointer picks inside that boundary. Standalone UI MS remains global. Explicit borrowed reference requests retain their rejection/cancel contract and navigation context.

**Minimal working test**

1. Open a frame, click a value field, edit it, then press Esc. **Expected:** The value edit cancels and focus returns to its parent.
2. Press Esc again at frame level; reopen it. Try M, W, then W again. **Expected:** The frame minimizes/restores; resize can restore its earlier size.
3. Expand several nested sections, then invoke Expand / collapse active descendants. **Expected:** Descendant sections collapse together. Closing preserves reopenable frames.
4. Resize with Shift+W, hover Full viewport and release Shift. Click the window body, minimize/re-expand it several times, then press W. **Expected:** No extra white wrapper border or unexpected position jump. Expanded cycles return to the selected viewport; W restores original size and position.
5. Open a target dial, a preset preview or a nested category. Left-click empty canvas/page space, or the blank dial centre. **Expected:** All open dials close together without drawing a dot or starting a drag. There are no dial × buttons. Chosen presets and accepted settings remain in the draft. Open a dial again and click an actual control: it still works; Escape/category Back retain progressive navigation.
6. Select Composer geometry, use its right-click DOF menu and nested configuration, cancel/accept a temporary reference, then invoke the DOF shortcut while using Master Controller. **Expected:** The geometry target and editor context persist through controller refresh and picking. Esc steps out of the editor before clearing selection; controller interaction does not redirect the command to another target.
7. In Composer select an object, press Q, select another, then move onto and click Master Controller or the Composer library button. Also tab into an outside field. **Expected:** MS cursor only applies inside the source surface. Outside controls receive the first click/focus, targeting ends, and accepted geometry membership remains. Q in Composer can start selection again. Standalone selector behavior and explicit reference requests remain available.

**Limits / unavailable behavior:** Website viewport sizing, not OS/browser fullscreen. Pinned frames reject resizing. Projected frames use W restore before dragging, under the existing rigidity policy. User acceptance pending.

## Universal Shift configuration

**ID:** `interface.configure` · **Status:** Implemented; browser verification pending

**Where:** Hold Shift and press the configured shortcut of the function you want.

Only relevant MC settings appear. Repeated shortcut presses cycle choices; hovering/focusing an option selects the temporary choice. Release Shift applies the selected choice once. Right-click applies and locks it; left-click resets to priority 1. Hover/focus does not change the saved default. Composer DOFs are the explicit exception: repeat the same active DOF shortcut to configure it, leaving Ctrl/Alt/Shift combinations assignable; see Composer DOF shortcuts.

**Minimal working test**

1. Activate a frame. Hold Shift, press W, then hover a different resize level without pressing W again. Release Shift. **Expected:** The pointed option becomes selected and previews its bounds; Shift release applies that option exactly once. Keyboard focus selects an option the same way.
2. Repeat Shift+W, right-click another option, release Shift, then use plain W. Repeat and left-click an option. **Expected:** Right-click applies and locks once; later Shift release does not execute again. Plain W uses the locked level or restores an active projection. Left-click resets to priority 1.

**Limits / unavailable behavior:** Shift release executes only an armed shortcut configuration. Explicit button-opened configuration remains unarmed. User acceptance pending.

**Verification:** browser — Focused local hover/focus release, no implicit lock, right-click locking and left-click reset checks pass. User acceptance pending.. ## Move, dock, select and organize UI

**ID:** `interface.arrange` · **Status:** Implemented; browser verification pending

**Where:** UI library; UI edit mode; shared frame/control context actions.

Drag actual frame handles or supported control edges. Docking offers destinations when a dragged header reaches another header. UI selection, alignment, compaction and reset are separate from knowledge structure. Window/frame drag previews reuse gesture-local target discovery and read-only docking policy results. Visual movement uses the latest pointer position once per animation frame, with geometry reads before transform writes. Release refreshes destination geometry and commits through the existing shared history; cancellation restores the live payload. Active-context shortcuts defer to a held UI gesture, so Esc cancels the drag before a parent minimize action. Pickup snapshots exclude descendants of the held frame/window and read visibility before lifting, reducing the expand-then-drag setup burst. Shared window interaction callbacks now commit on accepted click rather than mouse-down. Dragging a shortcuts window/title or other shared window cannot pin/activate it through onInteract. The existing global drag guard suppresses physical click tails even after source reparenting onto another surface, while keyboard/programmatic clicks remain usable.

**Minimal working test**

1. Create a UI frame, then drag a complete section into it by its handle. **Expected:** Its live controls move with it.
2. Hover another window without dragging; then drag a header over another header and choose a dock guide. **Expected:** Hover alone offers no docking. The deliberate drop docks the frame.
3. Select multiple UI controls and invoke Compact selected UI / Align UI. Undo. **Expected:** Selected controls rearrange; undo restores their UI arrangement without changing graph facts.
4. In UI edit mode, drag an expanded floating window across empty canvas, release it, then Undo once. Start another drag and press Esc before release. **Expected:** The window follows the latest pointer position. Release saves its final location; one Undo restores the prior layout. Esc cancels movement without saving a layout change. Report any visible frame skipping.
5. Hover-open Shortcuts, press and drag its window title; release. Then deliberately click it. Also drag a different function control, then activate it by keyboard. **Expected:** Mouse-down/drag never pins the hovered shortcuts window or executes the dragged command. A deliberate independent click still activates; Enter/programmatic activation is not swallowed as a drag tail.

**Limits / unavailable behavior:** Drag targets use a gesture-local discovery snapshot, refreshed at release. Browser traces are local diagnostics; user hardware smoothness acceptance remains pending.

**Verification:** browser — 2026-11-04 focused local Chromium drag regression passed five physical-input checks: hovered shortcuts window mouse-down does not pin; window drag does not invoke onInteract; a deliberate click afterward still works; dragging another command does not run it; keyboard activation after the moved command remains usable. ## Maintenance and known inventory boundaries

Every registered command and native gesture is covered by a walkthrough; the normal model/build entry points check coverage and generated-file freshness. Native controls, algorithms and workflows without a command require explicit catalog entries during implementation: their meaning cannot be inferred safely from code. The initial backfill groups some older graph workflows; subsystem guides retain their finer details. This is not a claim that every historical behavior has been independently browser-tested.

Before adding work, search this guide, the command IDs and subsystem references. Extend the existing owner when appropriate. Retire/redirect obsolete entries explicitly instead of leaving two competing instructions. Record user verification, date, source commit and reproducible failure when available.

Future workers: read [authoring contract](capabilities/README.md) and update the catalog in the same change.
