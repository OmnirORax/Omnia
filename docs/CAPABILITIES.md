# Omnia capabilities and how to use them

Generated from the reviewed capability catalog and the live command/gesture registries. Edit `docs/capabilities/catalog.json`; run `node --run docs:capabilities`.

This is the user guide and the first place workers check before proposing a duplicate feature. It describes this branch, not proof that every feature has reached production. **Browser acceptance is unrecorded unless an entry says otherwise.** Cloud rollout and provider configuration are separate from implementation.

Find a feature by name in the index or command table. Open the relevant owner/frame first: contextual commands can be unavailable until that owner is mounted. Custom layouts can move controls; UI search and Shortcuts show registered names and your actual saved bindings. Catalog defaults below may differ from your settings.

Use disposable work for tests; export your workspace first. Each numbered step includes its expected result. Record failures and observed results against the stable capability ID; do not mark a test passed from builds alone.

## Capability guide and automatic coverage checks

**ID:** `guidance.catalog` · **Status:** Implemented; generator and coverage checks verified

**Where:** Repository README → capabilities and user guide; bookmark docs/CAPABILITIES.md.

Reviewed walkthroughs explain features, exact entry points, limitations and observable tests. The command/gesture inventory regenerates from the application registries. Builds and model checks reject missing command coverage and stale generated guidance. A checked-in pre-push hook, installed per checkout with node --run hooks:install, blocks source pushes unless the working tree is clean at the pushed HEAD and local model tests, preview build and backend type checks pass. Artifact-only GitHack pushes skip duplicate source checks. Failed local checks do not reach GitHub and cannot trigger email. Delivery requires a passing local model/architecture suite before preview pushes, and requested behavior changes update matching assertions. Delivery batches verified source pushes; local frontend success, backend import checks, GitHub CI and browser acceptance are reported separately. Newer PR commits cancel superseded check runs without interrupting master releases.

**Minimal working test**

1. Open the repository README and follow capabilities and user guide. Search for Interpretive frame declarations. **Expected:** Its location, scoped tri-state behavior and explicit lack of constraint enforcement are visible.
2. Follow a capability’s numbered test and compare each expected result. **Expected:** You can report the stable capability ID and the failing step without reconstructing chat history.
3. For contributors: run node --run docs:capabilities, then node --run check:capabilities. **Expected:** The generated guide is current and every registered command/gesture has walkthrough coverage.
4. Before a shared portable-code delivery, run backend:check locally along with the applicable existing checks; push the completed batch once and inspect its GitHub runs. **Expected:** Deno import incompatibilities are caught before publication. Current PR runs supersede stale runs; master release ordering and all check jobs remain enabled. GitHub outcomes are reported separately from local checks.

**Limits / unavailable behavior:** Repository guide only; no in-app guide viewer yet. Automation checks coverage/freshness, not whether a human walkthrough or browser behavior is correct. Cancelling superseded PR runs does not recall sent email or change personal GitHub notification preferences.

## Active context, close, minimize, resize and descendants

**ID:** `interface.context` · **Status:** Implemented; browser verification pending

**Where:** Master controller → Active context. Click the intended frame first.

Actions target the clicked/focused frame. Esc steps out one field/popup level before minimizing; active MS has priority. W resizes/restores, M minimizes/restores, X closes, D toggles descendants, subject to saved bindings. Resized windows retain projected bounds and themed borders across focus and minimize/reopen. W restores retained original geometry. Projection styling is independent of React/Rnd wrapper updates. Left-clicking empty space dismisses all open contextual dials and requested dial editors, consuming that press so it does not also draw or begin a world gesture. Dial ×/close buttons are removed; the middle circle remains an unlabelled origin marker at full opacity. Category Back and Escape still step outward. Controls and rendered target roles retain their own click handling. Empty-space dismissal preserves chosen presets and accepted settings. Registered geometry surfaces now supply target adapters to the same commands and shortcuts; frame-only controls remain frame-only. MC discovers contextual controls from the command catalog rather than a parallel geometry toolbar. Delete selection and Compact are projected there. Popup/value-field Escape still precedes geometry scope and its parent frame. Shared active layers expose advance/confirm callbacks. Alt+MB4 steps outward, Alt+MB5 advances the nearest declared stage, Enter confirms, and Escape cancels or steps outward. Plain MB4/5 retain configured history behavior. Omnic dials have no Back/Confirm/checkmark navigation buttons; their centers only drag. Native input Enter remains local. Shared active-layer opening guards identify the physical press at window capture. Child React capture handlers cannot leave the native release guard armed for subsequent presses; only the original opener tail is suppressed. Keyboard-native activation retains its existing exception.

**Minimal working test**

1. Open a frame, click a value field, edit it, then press Esc. **Expected:** The value edit cancels and focus returns to its parent.
2. Press Esc again at frame level; reopen it. Try M, W, then W again. **Expected:** The frame minimizes/restores; resize can restore its earlier size.
3. Expand several nested sections, then invoke Expand / collapse active descendants. **Expected:** Descendant sections collapse together. Closing preserves reopenable frames.
4. Resize with Shift+W, hover Full viewport and release Shift. Click the window body, minimize/re-expand it several times, then press W. **Expected:** No extra white wrapper border or unexpected position jump. Expanded cycles return to the selected viewport; W restores original size and position.
5. Open a target dial, a preset preview or a nested category. Left-click empty canvas/page space, or the blank dial centre. **Expected:** All open dials close together without drawing a dot or starting a drag. There are no dial × buttons. Chosen presets and accepted settings remain in the draft. Open a dial again and click an actual control: it still works; Escape/category Back retain progressive navigation.

**Limits / unavailable behavior:** Website viewport sizing, not OS/browser fullscreen. Pinned frames reject resizing. Projected frames use W restore before dragging, under the existing rigidity policy. User acceptance pending.

**Verification:** browser — Empty-space dismissal, click consumption and nested dial closure await user testing. No browser suite run.. Automated — 281 model checks and type/build checks.

## Universal Shift configuration

**ID:** `interface.configure` · **Status:** Implemented; browser verification pending

**Where:** Hold Shift and press the configured shortcut of the function you want.

Only relevant MC settings appear. Repeated shortcut presses cycle choices; hovering/focusing an option selects the temporary choice. Release Shift applies the selected choice once. Right-click applies and locks it; left-click resets to priority 1. Hover/focus does not change the saved default.

**Minimal working test**

1. Activate a frame. Hold Shift, press W, then hover a different resize level without pressing W again. Release Shift. **Expected:** The pointed option becomes selected and previews its bounds; Shift release applies that option exactly once. Keyboard focus selects an option the same way.
2. Repeat Shift+W, right-click another option, release Shift, then use plain W. Repeat and left-click an option. **Expected:** Right-click applies and locks once; later Shift release does not execute again. Plain W uses the locked level or restores an active projection. Left-click resets to priority 1.

**Limits / unavailable behavior:** Shift release executes only an armed shortcut configuration. Explicit button-opened configuration remains unarmed. User acceptance pending.

**Verification:** browser — Focused local hover/focus release, no implicit lock, right-click locking and left-click reset checks pass. User acceptance pending.. Automated — 281 model checks, including pointed selection exactly-once release, unarmed sessions, defaults and layer reuse; build/type checks.

## Move, dock, select and organize UI

**ID:** `interface.arrange` · **Status:** Implemented; browser verification pending

**Where:** UI library; UI edit mode; shared frame/control context actions.

Drag actual frame handles or supported control edges. Docking offers destinations when a dragged header reaches another header. UI selection, alignment, compaction and reset are separate from knowledge structure. Window/frame drag previews reuse gesture-local target discovery and read-only docking policy results. Visual movement uses the latest pointer position once per animation frame, with geometry reads before transform writes. Release refreshes destination geometry and commits through the existing shared history; cancellation restores the live payload. Active-context shortcuts defer to a held UI gesture, so Esc cancels the drag before a parent minimize action. Pickup snapshots exclude descendants of the held frame/window and read visibility before lifting, reducing the expand-then-drag setup burst.

**Minimal working test**

1. Create a UI frame, then drag a complete section into it by its handle. **Expected:** Its live controls move with it.
2. Hover another window without dragging; then drag a header over another header and choose a dock guide. **Expected:** Hover alone offers no docking. The deliberate drop docks the frame.
3. Select multiple UI controls and invoke Compact selected UI / Align UI. Undo. **Expected:** Selected controls rearrange; undo restores their UI arrangement without changing graph facts.
4. In UI edit mode, drag an expanded floating window across empty canvas, release it, then Undo once. Start another drag and press Esc before release. **Expected:** The window follows the latest pointer position. Release saves its final location; one Undo restores the prior layout. Esc cancels movement without saving a layout change. Report any visible frame skipping.

**Limits / unavailable behavior:** Drag targets use a gesture-local discovery snapshot, refreshed at release. Browser traces are local diagnostics; user hardware smoothness acceptance remains pending.

**Verification:** browser — Focused isolated Chromium drag checks passed live payload, no persistence during movement, release commit, one-step Undo, Esc cancellation without minimizing, docking and one-step docking Undo. ## Horizontal spectrum slider

**ID:** `controls.spectrum` · **Status:** Implemented; browser verification pending

**Where:** Numeric property editors outside the Composer, including history Steps and visual parameters. Specialized spectrum/dial-size and snap configuration controls retain this path.

Drag anywhere on the track. Left-click endpoints selects min/max; right-click endpoints edits working limits. Right-click the dot types a value; right-click arrows changes jump size. Working limits cannot override hard renderer/semantic bounds. Manual value, limit and jump editors open as shared child popups at the invoking cursor point. Value/hover updates do not move them. The standalone ½ picker has been removed from the value slider. Prepared rule values use the same slider, with sequence traversal rather than uniform interpolation; minimum/maximum controls remain at its ends. Visible numeric readouts use six significant digits to avoid long floating-point strings crowding nearby controls; exact values remain in tooltips, accessible/native inputs and owner state. The slider declares its whole compound control as a popup boundary, allowing shared child editors to avoid covering its controls. Relative DOF-icon grabs use the shared free-space value scrub: the first three-pixel movement locks a horizontal, vertical or diagonal axis for the drag, further motion projects onto it, and reversing decreases the value. Primary selection and contextual Enter confirm the same prepared value through shared owner callbacks. Axis/linear/plane/math-dial projections register shared value confirmation; held sliders register the existing finish transaction for Enter. The popup wrapper no longer has a duplicate opening-release boolean: the shared physical-press guard alone protects the actual opener tail. Nested navigation resolves each action independently, so a cancel-only child does not mask confirmation.

**Minimal working test**

1. Drag from an empty point on the track, rather than the dot. **Expected:** The value follows the pointer continuously.
2. Right-click the dot, enter a value, then right-click an endpoint and an arrow. **Expected:** Manual value, working bound and jump editors appear for the corresponding parts.
3. Select an endpoint and undo the completed property edit. **Expected:** The value reaches the supported endpoint; undo restores the prior committed setting.
4. Preview a new value with the axis wheel, on-spot linear/position field or math dial. Accept with one deliberate left click, then repeat using Enter. Also press Enter during a held value-slider edit. **Expected:** Both inputs commit through the same owner. Leaving retains the committed result; no repeated clicks or confirmation button is needed. Invalid/disabled/no-candidate states do not commit.

**Limits / unavailable behavior:** Composer value editing now opts into ⠒❉; outside editors and specialized slider controls retain this implementation. Browser acceptance has not been recorded for this guide.

**Where:** Omnic Composer → right-click empty space → ↱ Path rule. Existing paths: right-click their trace → Path rule. No reference selection is required for rule authoring.

A circular cardinal-direction editor appends numbered instructions in click order. Each instruction has a whole-unit count edited with the existing math dial. Configure a constant quarter turn after each instruction, looping and closure; fixed generation defaults to at most 100 unit moves. Drawing uses the same traversal with a glowing particle and existing Play/pause. Connected substrate cells or separate marks share additive coverage per traversal, capped at 100%. Creation captures the current substrate bounds, including the radar circle; a blocked whole-unit move pauses. Playback retains elapsed time and its displayed frame on pause, replays after completion and resets after rule edits. Rule changes use existing preset/target setters and history. Spatial transforms cannot bypass the substrate unit contract. Path-control button styles are scoped to their own rows/wheel; embedded math dials retain their native slot sizing, appearance and cursor styles. Switching a populated rule into drawing starts playback. The path editor registers its Play/pause alias explicitly. Idle embedded math dials yield Enter to the parent rule editor; pending hovered candidates retain confirmation priority. Drag the frame/title or empty rule-panel background to move the entire rule popup through the shared popup drag mechanism. The rule editor uses its existing popup controller rather than declaring a nested controller. Embedded numeric dials retain sampled values until commit/cancel rather than resetting the stroke from stale props. The shared tool cursor uses the browser top layer and raises on popup transitions, keeping it above contextual popovers. Preview continuity now belongs to the shared mathematical-value session, with optional live-preview callbacks. Commit-only consumers inherit it automatically; the path-specific sample wrapper is removed. Real changed external values still reset scratch state. Clearing the last mathematical mark restores the legal neutral value (1 for positive counts), rather than retaining the previous count. Zero-capable domains keep zero and increment rules keep their anchor. Continuous rendering now joins collinear whole-unit edges into smooth vector strokes with round caps; discrete rendering retains separate marks. Traversal resolution remains one unit. Shared math-dial chrome now has no reading-direction toggle or separate base buttons: click its centre to switch base 1/2. Readout, ring, sign and clear controls sit vertically to its right across all math-dial consumers. Shared math slots now apply recursion immediately on right-click. Left-click/held painting uses normal values and selection/deselection; there is no cursor brush cycling. Starting a new sequence closes the old count editor; its first direction starts at one unit with turn, Loop and Closure reset. Presentation settings remain. The new instruction count editor opens fresh. Direction and turn selection now reuse the rotation DofAxisWheel with adjustable fractions, initially 2³ (8). The fraction expression opens the shared math dial. Cardinal thresholds stay available; instruction ordering accumulates without closing the wheel. Non-cardinal headings still travel whole-unit distances. Frame dragging now yields to all declared embedded popup/control interiors, so direction-wheel presses append instructions instead of starting a frame drag. Explicit centre/title drag handles retain priority. Each accepted wheel direction appends a numbered instruction, selects it and immediately opens its own count editor. Existing order, other instruction counts and authored origin remain intact.

**Minimal working test**

1. Right-click empty Composer space and choose ↱ Path rule. Click ↑, →, ↓, ←. **Expected:** The circular editor opens immediately, with no MS request. A fresh rule contains no instructions; clicks become instructions 1–4, each initially one unit. The trace updates in that order.
2. Click a numbered instruction or the wheel centre, then change its count using the math dial. **Expected:** Only that instruction changes. Counts are positive integers; no fractional or zero move is accepted. The selected chip shows the count.
3. Use ↺ to load the example square, then inspect ↻, ⟳ and ⊙ through their tooltips. **Expected:** ↑2, turn 90°, Loop and Closure generate an eight-unit square with side length 2. Closure stops at the origin after a complete sequence.
4. Disable Closure, set per-pass coverage to 10%, and set the fixed maximum to 80 moves. **Expected:** The square is traversed ten times and every visited cell reaches exactly 100% coverage. Increasing the maximum does not increase saturation beyond 100%.
5. Switch to Drawing mode, use its Play/pause control, pause and resume; then enable Closure and replay. **Expected:** The glowing particle follows unit moves. Pausing retains the trace and resuming continues its clock; closure retains the final frame. Replay after completion starts from the origin. Editing a rule starts a fresh run.
6. Create a straight path toward the substrate edge; toggle separate marks/connected trace and inspect the ≤100 limit. **Expected:** The next whole cell must fit inside the captured bounds, including the radar circle. No partial final move is drawn. Trace style changes neither movement nor deposition; fixed generation counts unit moves, not instructions.
7. Close and reopen an existing path through its target DOFs, edit a count, then use Undo. **Expected:** The same rule editor opens directly, without an MS reference request. The program persists and the normal history restores the previous accepted rule.
8. Drag the frame/title or empty panel background, switch a populated path into drawing, use Play/pause, then move away from math slots and press Enter. **Expected:** The popup moves without editing instructions. Drawing starts; Play/pause remains available. An idle math dial yields Enter so the rule popup can confirm.
9. Open a math count dial and right-click an available slot, then left-click it to deselect. **Expected:** Right-click immediately selects the recursion contribution and updates the value, without a second left-click. Left-click removes the selected slot.
10. Load the square example, open a large instruction count, press ＋ and select any direction. **Expected:** A fresh one-unit instruction replaces the sequence. Loop, Closure and turn are reset; the old count editor is discarded. With fixed mode active it draws one unit rather than repeating to the boundary.
11. Open a path rule, click its 2³ direction-fraction expression, change it to 7, then select a direction. **Expected:** The same angular wheel used by rotation offers generated fractions plus preserved cardinal thresholds. Selecting appends a direction; a one-unit instruction travels exactly one unit.

**Limits / unavailable behavior:** First experiment: cardinal directions and quarter turns, eight ordered instructions, 1–100 units per instruction, fixed cap 1–10000 moves (default 100), additive coverage 1–100%, speed 1–60 units/s. One-unit movement resolution; continuous output uses vector segments; no sub-unit movement or subpixel paint accumulation. Captured substrate bounds are not yet editable. Each trajectory is bounded to 192 cells/4096 transitions, with 32 cached plans and existing aggregate animation safeguards. Playback/saturation snapshots are transient; no durable painted-substrate storage, branching, bounce/wrap or multi-reference generation. Ordinary geometry transforms are unavailable on substrate-bound paths; use their rule and whole-unit Position.

Nested math-dial clicking and cursor visibility need user confirmation after isolating path-control styles. Automatic drawing start, the registered Play alias and idle-dial Enter handoff await user confirmation. Preview handoff and top-layer cursor visibility require user verification in this revision. Shared-session inheritance awaits user acceptance. Direction selection with frame dragging enabled awaits user confirmation.. Automated — Model regressions exercise ordered/compressed square equivalence, minimum-unit and import validation, closure ordering, boundary and fixed limits, additive 10%/1% saturation, time-independent coverage, periodic loops, saved reconstruction, SVG projection, target editing and transform guards. Local test/type/build/backend gates run before delivery. Regression tests cover unchanged committed props during local preview, commit/cancel, external replacement and existing preview-echo consumers. Shared frame-ownership regressions cover axis-wheel descendants, buttons, frame backgrounds and explicit wheel-centre handles. Angular-authoring regressions preserve click order and isolate selected-instruction count edits..

## Maintenance and known inventory boundaries

Every registered command and native gesture is covered by a walkthrough; the normal model/build entry points check coverage and generated-file freshness. Native controls, algorithms and workflows without a command require explicit catalog entries during implementation: their meaning cannot be inferred safely from code. The initial backfill groups some older graph workflows; subsystem guides retain their finer details. This is not a claim that every historical behavior has been independently browser-tested.

Before adding work, search this guide, the command IDs and subsystem references. Extend the existing owner when appropriate. Retire/redirect obsolete entries explicitly instead of leaving two competing instructions. Record user verification, date, source commit and reproducible failure when available.

Future workers: read [authoring contract](capabilities/README.md) and update the catalog in the same change.
