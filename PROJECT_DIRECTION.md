# Omnia direction

Omnia is intended to become a shared environment where humans and AI construct, explore, understand and manipulate knowledge through structured nodegraphs.

- **Omnium:** a genuinely three-dimensional, spatial, hierarchical nodegraph. Three-dimensional space is essential.
- **Omnic:** a future visual and structural language using nodes, symbols, typed operators, relationships, nesting and possibly spatial arrangements. Its grammar is still undesigned; do not invent it during implementation.
- **AI access:** AI should eventually read and modify graph data directly through structured operations, without screenshots or English as an intermediate representation.
- **Semantic independence:** graph meaning and identity must not depend on a renderer, appearance, spatial layout or English labels.
- **Extensibility:** Omnic should be able to grow without repeatedly rebuilding Omnium.

For each task, implement the requested capability with the smallest compatible change. Preserve existing functionality and user data. Keep semantic graph data distinct from view state, make costly-to-reverse decisions explicit, and avoid speculative features or abstractions.

Verification preference: the user performs testing. Prioritize implementation; skip routine test suites, browser checks and extra test-writing. Use a small targeted check only when genuinely unsure about a concrete implementation issue. Avoid expensive regression work unless explicitly requested. Build only when needed to produce the requested preview/artifact. Human testing determines usability and design fit.

The interface is user-arrangeable: individual global functions/settings can float, snap into named frames whose outline follows their slots, use text or icon buttons, and be pinned. Windows are draggable, resizable and collapsible. Entity-specific context menus retain fixed membership and the clicked entity; only internal order, shape and size are customized. UI templates are portable presentation configuration, separate from canonical graph knowledge.

The user authorized a coherent developer-arranged baseline to reduce clutter. `src/ui/default-template.json` is the shared default for first use and Reset to default: File/Create/View/Workspace groups, a small charting toolbar, Hierarchy and Inspector first, and advanced sidebar panels collapsed. Groups reuse the same draggable/dockable window and function infrastructure. Existing saved/custom layouts stay in place until explicit reset; the organized toolbar is selected by the portable `panels["@organized"]` flag. Reset is one undoable UI-only transaction and preserves graph data, keybindings and mouse/spatial preferences. Keep controls reset separate. A later user-authored template can replace this baseline without rebuilding the UI or changing knowledge.

UI frames can contain frames/windows, with measured contours and drag bounds around actual residents rather than saved wrapping widths. Fields travel with their labels via edge dragging; input editing remains distinct. UI dragging preserves chosen positions; anchor/grid snap mode has been retired, including its workspace and container controls. Old templates remain readable, but their grid metadata has no placement effect. Floating embedded groups measure their natural payload with ResizeObserver; a separate viewport applies screen/dock limits. Never feed a previously clipped wrapper size back as the payload's maximum, or moving/expanding the group can permanently truncate its controls. A frame's identifying tab stays fixed when its background moves its contents together. Click its handle to collapse/expand; pin and close live in its context menu, without visible mini controls. Entity menus use the same arrangement surface but retain fixed membership and the current target. UI layout/settings have their own undo history (Shift+MB4/MB5), independent of graph history. UI containment never asserts structural knowledge.

Compact operates on selected placements, or the whole atlas with no selection. Shorten each child's parent-local vector independently, keeping its existing direction; compact branches bottom-up and move each whole branch with clearance for its expanded contents. Root-level groups contract toward a stable existing root near their center (prefer a fixed, unselected root when present). One close pair must not block unrelated branches. Preserve the recognizable arrangement rather than enforcing identical distance ratios across the atlas. Fixed/unselected placements keep their local coordinates; unselected descendants follow moved parents. Identities, charted facts, visual sizes and legacy 2D coordinates stay untouched. This explicit action ignores coarse drag-grid spacing and is one undoable graph operation. Coincident anchors have no authored direction and are not arbitrarily scattered.

Focus context only is an optional, locally persisted view toggle. Explicit camera focus displays its root placement(s), their visual subtrees and their ancestor paths, intersected with existing frame, collapse and variant visibility. Adding ancestors must not reveal their sibling branches. Unrelated nodes/binders are not rendered or selectable; Select All uses the visible context. Focus does not alter canonical knowledge, placement-hidden flags, frame scope or collapse state. Back restores the earlier camera, roll and context; Fit entire atlas clears isolation for that view while leaving the toggle enabled for the next focus. Selection, hierarchy clicks, editing, creation, nesting, expansion, import and layout operations do not automatically move/refit the camera. Use explicit Focus/Fit/navigation actions. Initial view is anchored to the world origin.

Zoom uses stable physical geometry: labels, images, GLB models and binders keep their world size and authored positions as the camera moves. Remove camera-driven sideways node separation and binder-driven node displacement. Flat text/icons occupy world XY planes rather than always facing the camera, so they may tilt, become edge-on or mirror from behind. The movable camera guide shows zoom %, XYZ orientation, camera/target/selected-node world coordinates, and a compass for fixed axes at (0,0,0). 100% is the default camera distance/FOV at the current orbit target; it is not reset after each focus. Explicit 90° roll controls provide inverted views through the existing OrbitControls API. Frame projections retain world positions when parents are filtered, while edits retain canonical parent-local storage; these coordinate helpers are shared in `src/graph/coordinates.ts`.

UI buttons have a separate transient selection: Ctrl/Cmd-click, Shift-click for an inclusive range from the last clicked item, or the Select UI buttons box tool. Ranges follow visual reading order among peers in the same frame/collection, skip hidden or pinned items, and keep their anchor when extended/reduced; Ctrl/Cmd+Shift adds the range to the existing selection. An ordinary click clears the selection (including a click on a selected item without dragging); input/canvas clicks keep their normal action. Right-click Lock selection retains highlights during unrelated interaction; Unlock restores automatic dismissal. Explicit Clear/Esc still releases the selection, and Ctrl/Shift can deliberately change its membership. The lock is transient selection state, not frame pinning or saved graph/UI data. Selection tools and alignment menus retain their targets. Clicking fields for editing keeps normal input behavior. Group dragging preserves relative positions, and can transfer it between expanded frames or float it in the workspace. Context-owned actions cannot leave their menu; pinned buttons/containers reject movement. Compact selected UI packs measured buttons with a small gap, preserves frame membership and unselected neighbors, and is one UI-history operation. Drag-release clicks never activate actions; a new deliberate press works immediately. Alt+MB4/MB5 traverses five graph-history entries; Shift+Alt traverses five UI-history entries. Both clamp at available history.

Align UI uses the shared selection and placement systems. Right-click selected UI items and hover Align for a flyout; unselected frame menus can align that frame too. Choose selection bounds or the app window, then align edges/centers or distribute equal horizontal/vertical gaps (at least three items). Align UI also exposes the same registered, movable/editable controls in a window. Keep sizes, the other axis and frame membership; each command is one UI-history operation. Pinned items stay protected. Structured dock panes keep their split/tab geometry and must be dragged out before individual alignment. Portaled submenus share their parent menu's outside-click boundary and stay above window layers.

Native inspector/settings/shortcut fields reorder as siblings with before/after previews; a field is never another field's container. All four field edges share bounded grab targets, separate from frame dragging. Use the frame handle as the explicit nesting target. The categorized, searchable UI library exposes live actions and setting editors, supports drag-out placement, and remains accessible through Ctrl+Alt+U. Context-specific fields retain their IDs and explain when their editing context is unavailable.

The current workbench is 3D only. Its version-2 document separates identity, charted composition and typed relationships, placements, and investigative frames. A visual parent is not a semantic parent. Version-1 authored `parentId` values migrate into both kinds of link. External AI contributes through revision-checked JSON operations that require human review; structurally valid proposals do not establish epistemic truth. Retain legacy 2D coordinates in imported data, but do not rebuild a 2D editor unless the user requests one.

Nodes currently appear as full world-oriented text bars centered on their placement anchors, replacing spheres. Future symbols/icons/structural renderings must preserve those referent IDs. Directional binders distinguish charted composition, typed relationships, and visual-only nesting. Binder operators are editable text annotations pending user-authored Omnic grammar. Color/opacity and saved coordinate views are presentation state. Hierarchy and user-configured flow ordering may rearrange coordinates, but must never invent relationships or change canonical identity.

Single-click opens developer-defined node options (currently Variants); double-click expands/collapses structural contents. Variants are owned canonical references with a separate hidden-by-default expansion mode and a reserved add control. Ownership is not authored structural composition, and revealing variants must never clone internal knowledge or create structural children. Option categories are extended in source code only.

A variant is otherwise a normal node, including its own authored children, deeper structures, relationships, reusable referent, context menu, inspector, and shortcuts. Use ordinary placements with an explicit owner visibility gate; do not introduce restricted stand-in nodes or separate editing paths. Closing a variant mode hides its displayed subtree without changing its knowledge. Multiple references share canonical identity while retaining independent placement state.

Node and binder visuals can combine text, Unicode characters, Iconify/custom images, and self-contained GLB assets. Store portable resources once, reference them from presentation state, and retain canonical text/IDs independently. Binder display text and symbols do not redefine relationship meaning. Layout, connectors, raycasting and rectangle selection use actual world-space visual footprints; the camera must not introduce a second apparent node layout.

Delete on a selection removes its canonical concepts and subnodes globally, including other representations and owned variants. Warn about shared/outside references and preserve the entire prior document for one-step undo. Representation-only removal remains explicitly separate. Ctrl/Cmd-drag selects; Shift gestures retain subtree expansion/nesting by default. Keep the hoverable, editable shortcut display and keyboard/mouse handling connected to the same action registry.

Shift-click (configurable) expands every charted structural level beneath a node, or collapses a fully expanded subtree, in one undoable operation. This reveals references without inventing facts; it is distinct from Shift-drag nesting and from variant expansion.

Appearance reuses CSS and existing Three.js addons: default Neon, switchable Classic, editable accent/background, bloom, panel opacity/blur and optional Stars/Dust/Sparks. The dedicated Theme / aesthetics window is part of the default UI. Appearance belongs to local UI settings/templates, never knowledge; authored colors take precedence. Subtle optional motion is capped at 30 fps, pauses in hidden tabs, respects reduced motion and does not rebuild graph geometry per frame. With motion off, rendering is on demand. Zero glow bypasses post-processing; unavailable effects fall back to ordinary rendering.

An unnamed node/variant without an asset is a sphere, default diameter 1 (radius 0.5). Nonempty visible text replaces it with a label box; an asset replaces it with that asset and optional text. Empty text never renders an Untitled box. Stable IDs and existing authored names survive representation changes. Shared visual footprints drive placement, compaction and framing; sphere connectors meet their surfaces. Picking volumes never become visible on hover/selection. Use restrained outlines and protect icon details from bloom. Binders use Three.js screen-width antialiased lines. Keep the movable camera compass, without world-origin axes in the scene.

Theme resolution is global accent → Nodes/text or Binders defaults → individual presentation override. Binder labels use Nodes/text defaults and optional textAppearance; binder line/operator styling must not recolor or fade its label. appearance.glow and textAppearance are optional, backward-compatible presentation fields. Keep bloom separate from base brightness: zero per-item glow preserves the object; emitted hues follow authored colors, including native asset palettes. Limit bloom to close blur scales to avoid broad haze. All new theme settings remain local/template UI state, never canonical facts.

The Theme editor now uses a shared hierarchical property controller, replacing the older Global/Nodes/Binders modes. See [the shared appearance controller](docs/APPEARANCE_CONTROLLER.md) for targeting, plugs, property locks, local refinements and extension points. This supersedes the earlier SVG recoloring policy: native graph SVG/PNG/model palettes retain their authored colors, while text/geometry use defaults unless locally authored. Effects, brightness and opacity remain independently adjustable. UI icons can receive an explicit UI tint. Sparkle animation remains pointer-transparent, bounded, outside canonical data, reduced-motion aware and paused in hidden tabs.

UI additions must follow [the shared UI component contract](docs/UI_COMPONENT_CONTRACT.md): actions, fields and complete expandable groups use the same ownership, drop validation, customization, undo and persistence paths. Do not add draggable headers that leave their live contents behind.

## Editable UI contract

Use `UISection` for categories/headings with contents, `UIField` for a label and its live input, and `UIAction` or the action registry for buttons. Give each a stable ID independent of its editable name. These components inherit moving, nesting, selection, styling, closing, search, history and template persistence; do not create fixed markup equivalents beside them. Reuse a neighboring component in the same category before adding an adapter.

UI edit mode places existing registered controls and creates custom UI-local fields. UI labels, custom field values and layout stay separate from canonical graph knowledge. Custom fields do not acquire new computational behavior merely by being placed. Default definitions remain in code and the built-in UI template; Reset to default restores that reference. The emergency appearance recovery panel deliberately remains independent of customized UI. UI edit mode’s coverage inventory identifies visible fields/headings that bypass this contract; use it when adding a new window.
